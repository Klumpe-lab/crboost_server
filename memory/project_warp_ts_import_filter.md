WarpTools `ts_import` (the job we wrap in `drivers/ts_import.py`) runs a hardcoded intensity filter at `WarpTools/Commands/Tiltseries/ImportTiltseries.cs:335-350` that walks outward from the 0-tilt index in tilt-angle-sorted order and truncates everything past the first tilt failing `AverageIntensity >= MinIntensity * cos(angle) * MaxAverage * 0.999f`. Plus three other per-tilt drops (`UnselectManual`, `|angle| > MaxTilt+0.05`, `MaskedFraction > MaxMask`).

**Why:** Discovered on test3_/test4_20251113_412 when `TsAlignmentIngestAdapter.emit_star` failed with "frame X has no alignment in registry output (tomostar did not include this movie)" on 6-7 frames per TS. Verified via sha256 trace that our code doesn't touch row counts — WarpTools wrote the short tomostar directly. Deepwiki + source confirmed: cannot be disabled (CLI rejects `--min_intensity < 0`), silent (no verbose flag, no log of dropped tilts), and zero-mean motion-corrected MRCs can produce negative-median `AverageIntensity` that fails `>= 0` even with `MinIntensity=0`.

**How to apply:** If a pipeline failure mentions a tilt-count mismatch between per-TS STAR and tomostar / alignment / CTF output, this filter is the prime suspect — not our code. Verify via `wc -l` comparison: `Import/job001/tilt_series/{TS}.star` (mdoc count) vs `External/job00N/tomostar/{TS}.tomostar` (post-filter count). Downstream WarpTools (`ts_aretomo`, `ts_ctf`, `ts_reconstruct`) treats the post-filter tomostar as the authoritative frame set per `WarpLib/TiltSeries/TiltSeries.cs:311-359` — it never re-reads `warp_frameseries/*.xml`, so filtered frames are simply absent from reconstruction. We match this at the adapter layer by skipping un-matched rows in `_apply_alignment_to_tilt_df` and `_apply_ctf_to_tilt_df` (mirrors `CryoBoost/src/warp/tsAlignment.py:132-140`). Output STARs retain all N rows; filtered rows carry NaN alignment columns / the per-frame CTF values from fs_motion_and_ctf. Never try to "disable" this filter by lowering `min_intensity` below 0 or re-injecting rows into the tomostar without understanding that AreTomo may produce garbage on zero-signal tilts.
