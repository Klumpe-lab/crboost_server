Design rules the user gave for `ui/tomo_dashboard_dialog.py` (the Journey dashboard) on 2026-05-20. Apply these to future dashboard work without re-litigating.

**Slabs (X/Y + X/Z) must sit LEFT of the gallery, side by side — not stacked above it.**
- **Why:** the gallery↔canvas hover cross-link is only useful if you can see the tile AND its dot on the slab at the same time; stacked vertically you can't.
- **How to apply:** the Particles section is a 2-column split (canvas left, tabs/gallery right). Don't revert to a full-width-stacked canvas. (The user initially picked "stacked" in a PR1 question, then reversed once they saw it — side-by-side is the settled answer.)

**Keep the Reconstruct section's tomogram preview as the WarpTools PNG, and never overlay picks on it.**
- **Why:** the recon preview is the raw-reconstruction reference; conceptually it's recon's output, not a candidate-job result. Our own slab render looked washed-out and its X/Z strip read as an ugly "black streak". The user explicitly said bring back the previous (WarpTools PNG) and keep it clean.
- **How to apply:** recon section → `_render_recon_big_preview` (WarpTools PNG, X/Y only, no Invert). Picks + X/Z slab + Invert live ONLY on the Particles canvas. Our X/Y+X/Z slab render is still used there (it's needed for the pick overlay + Invert + X/Z depth view) — just not in the recon section.

**Keep the whole page compact and light-fonted.** The user called the chrome too heavy/dense-in-a-bad-way. Prefer small sizes, `font-weight 600` over `700`/bold, tight padding/margins. When adding UI here, lean lighter than the NiceGUI/Tailwind defaults.

**Pick-dot ghosts: tiny, crisp dual ring, and active = backlight NOT expansion.** As of 2026-05-21 the settled treatment (`.cb-pick-ghost`): 3px dot, species color (`var(--sp-color)`), high-contrast dual ring (solid dark inner `rgba(0,0,0,1)` + bright white outer). Active/hover does NOT change size — it adds a subtle colored glow (`0 0 6px 1.5px var(--sp-color)`). The user explicitly rejected the old 9px orange expansion ("no need to expand the dot when it's active … we are not blind"). Contrast comes from the ring, not the dot area. (The separate moving `.cb-pick-marker` — the pink locator that tracks a hovered gallery tile — was left unchanged; flag if it should be toned down to match.)

**Hover cross-link must keep exactly ONE dot active.** The bridge clears all active state at the start of every mouseover (clear-then-set) and only tears down when the pointer leaves our scope entirely; tile→tile moves no longer accumulate stuck `.cb-ghost-active` dots (the 2026-05-21 sticky-dots bug).

**TS roster rows = two stacked tracks (settled 2026-05-21).** Per row: derived title (`Pos N · Beam M`) + a ⓘ click-popover (NOT hover — copy buttons need a persistent popover) holding full tomo name, `Å/px · dims`, and file paths each with a copy-full-path button. Then a `prep` track (the 4 array stages as a fixed-segment bar) and ONE line per species (color dot matching the canvas/tab color + pick + subtomo segments + pick count). Full tomo name is OUT of the row (in the popover). Helpers: `_collect_species_journey`, `_render_ts_info_popover`, `_PREP_STAGES`.

**Sidebar selection must NOT rebuild the sidebar.** Switching TS toggles the `.selected` class on cached row elements (`row_els`) + re-renders only the main pane. Rebuilding all rows on click (the old path) dropped in-flight clicks → "have to click twice". The 4 s live timer's sidebar rebuild is gated on `_journey_signature` (FingerprintedView discipline) so progress ticks don't tear down rows under the cursor.

**X/Z slab must render at the SAME width as the X/Y slab above it.** Geometric match — same x-axis scale. Implemented via one width-constrained `.cb-canvas-stack` wrapper (capped to keep X/Y ~52vh tall); both children are `width:100%` and derive height from their own `aspect-ratio`. Don't give X/Z an independent height-based max-width again (that's what made them mismatch).

**Per-species tab layout (settled 2026-06-08, SUPERSEDES the old "Option A header").** The gallery/detail is the dominant element; the tab header was fully dismantled (Slice B items 3–6 + follow-up fixes). Settled rules:
- **Per-species generate controls (Render previews · Re-render all · (Re)generate IMOD) go in the PARTICLES PANEL TITLE BAR, next to the canvas-wide Invert switch — NOT inside the tab body.** The user was emphatic ("next to invert switch") and I got it wrong once by putting them in the tab body. They follow the active species tab (re-rendered on tab switch via `_show_admin_for` + `tabs.on_value_change`; `_render_species_admin_buttons`). Invert is section-level/canvas-wide (shared across species); the three generate icons are per-species.
- **The pick-list rail (chips) sits ABOVE the gallery as a HORIZONTAL strip — NOT a narrow column beside it.** A short rail left of a tall gallery left "long vertical whitespace"; stacking it on top fixes that and gives the gallery full width. `.cb-workbench-split` = column; `.cb-list-rail` = horizontal flex-wrap row; chips `flex:0 0 auto` content-sized; the Curate/Import/Merge toolbar is `margin-left:auto` (right-aligned).
- **The old inline gray stats (pos · tomo · N · score · θ · sym · Ø) + the TM line moved to a hover tooltip on the pytom chip's type tag** (`_attach_auto_chip_tooltip`). The **size pills (`_render_tm_size_chips`) were DELETED** — they duplicated the Dataset section + `pixel_sanity.py` (user: "delete it, I care more about readability and clarity of the interface than some random metric"). **3dmod moved to the BOTTOM** of the tab. Each pick list is a chip tagged by type (pytom / manual (ArtiaX) / imported / merged), with per-list + per-species master visibility eyes (eyes drive the canvas dot layers; the old "Show picks" checkbox row is retired).

**Species tabs: small / slate / no-caps, thin indigo indicator, + a per-species color dot.** The dot is a CSS `::before` on `.q-tab__content` driven by inline `--sp-color`, tying each tab to its canvas overlay color. NOTE: NiceGUI `ui.tab(name)` forces `label=name` when label is None, so custom-slot tab content double-renders the id — use the `label=` prop + CSS dot, not slot content.

**The gallery↔canvas hover cross-link must survive tab switching.** Quasar `q-tab-panels` unmounts inactive panels, so a one-shot `getElementById(gallery_id)` at render bails for non-default tabs (the "hover does nothing on the 2nd tab" bug). Fix: delegate mouseover/mouseout on the always-present Particles `.cb-section-card` (common ancestor of canvas + all panels) and resolve the grid lazily at event time; filter each per-species bridge to its own grid + its own `.cb-pick-layer` ids so the N bridges on the shared card don't cross-fire.

**Gallery cutouts go ON TOP; metadata compacted BELOW; Save/Reset stay in the header (2026-05-21).** In `_render_gallery_body` the cutouts (title + reference strip + grid, `cb-gallery-scroll` capped ~68vh) sit first in a `cb-cutouts-box`. The cutouts HEAD also holds the always-visible action buttons (Save picks / Reset this tomo) in a right-aligned `actions_slot` (`with actions_slot:`). Everything ELSE — hover-stats strip, sort, kept counter + exclude-not-extracted box, filtered-set path — goes into `cb-gallery-controls-box` rendered after the grid. **GOTCHA that bit us:** initially the WHOLE filter toolbar (incl. Save/Reset) was moved below the grid → buttons fell off-screen under the tall grid ("where did the save buttons go"). Fix = action buttons in the header, only the metadata below. The user's "move below" list never included Save/Reset. Implemented WITHOUT mass re-indent by re-parenting blocks via `with controls_box, ui.row(...):` / `with cutouts_box:` / `with actions_slot:` / `with controls_box: path_row=...`.

**Box-select (lasso) on the cutouts — ALWAYS ON, no mode button (2026-05-21 revision).** A plain click on a tile still toggles keep/drop; a click-DRAG over the cutouts panel draws a `.cb-lasso-rect` and acts on everything inside. Single document-level delegated marquee (`window.__cbLassoInit` guard; resolves the grid via `closest('.cb-gallery-scroll')` so it survives q-tab-panel mounts). Click-vs-drag = a 5px movement THRESHOLD: under it, do nothing (let the tile click fire); over it, draw the rect (add `.cb-lasso-dragging` for crosshair + `user-select:none`, `preventDefault` on mousemove). On mouseup collect enclosed tiles' `data-pick-idx` (center-in-rect, skip degenerate) AND count how many carry `cb-tile-dropped` → dispatch `cbpicklasso {idxs, keep}` → Python `_on_lasso` unifies them. **Symmetric/majority direction:** mostly-kept box → DROP all; mostly-dropped box → RESTORE/KEEP all (so a drag deselects too); Shift forces keep; ties drop. (Earlier it was always-drop / Shift-keep — the user wanted deselect-by-drag.) The synthetic post-drag click is swallowed via a capture-phase `window` click listener removed on `setTimeout(0)`. Do NOT use `pointer-events:none` on tiles (clicks must keep working) — the swallow handles the stray toggle. The earlier button-toggle `cb-lasso-active`/`cb-lasso-btn`/`pointer-events:none` approach was removed.

**Dropped (excluded) cutouts: red border + thin diagonal red stripes ONLY — no opacity dim.** The user found the old `opacity:0.32` a "harsh foggy white" that hid features; removed it. `.cb-tile-dropped` now = red 1px border + box-shadow + the `::after` repeating-linear-gradient red stripes. Keep dropped cutouts fully visible.

**Phase 2 (agreed 2026-05-20, NOT yet done): unify the WHOLE journey section's visual language.** Denser, more compact, less colorful, lighter chrome. Model it on the subtomo gallery's minimalism — "highlights really minimal and in the right places"; everything else is "a circus" right now. To be done once the bug/layout fixes above are verified functional in-browser.
