## recon:ci_feasibility: What CI could check today, measured on this checkout (local, read-only)

I ran every check the brief listed twice: once in the working tree and once on a `git archive HEAD` export in scratch, using a throwaway HOME and a conf.yaml/qsub.sh copied from the templates. So every failure below is in committed code, not in the uncommitted roadmap_53 edit or the untracked _vol_toy.py.

Most checks already pass and are ready for CI:
- ruff check: clean
- check_boundaries.py: R1–R5 clean
- compileall: 432 files compile
- imports: all 396 modules import except the 4 torch modules under filterTilts/deepLearning, which by design run only inside the tilt_filter container
- the shipped copia-tutorial protocol validates with 0 problems
- the lock is in sync with requirements.in
- the qsub template's exit-marker block matches QSUB_EXIT_MARKERS
- the conf template parses into Config with no unknown keys

Two gates fail on committed code:
- `ruff format --check`: 48 committed files would be reformatted. 20 of them are services/jobs/* files whose assignments were aligned by hand, which the formatter undoes.
- `check_look_literals.py`: 11 ui/ files are 76 literals over the allow-list. The allow-list was written 2026-11-13 and broke within 6 days. Nothing runs the checks automatically, and that is the case for CI.

There are no workflows, no .github directory, no pre-commit hook and no Makefile. All the checks are documented in CLAUDE.md or the roadmaps and none is wired to anything.

`./crboost test` passes 5/5 here. On a template conf it gives 3 passed, 1 skipped and 1 failed. The failure is test_preflight_checks_pass, which by design checks a real site (tool paths, partitions, sbatch on PATH). So a marker split or a template-driven repo test is enough to run the static tier in CI. Roadmap 39 S4's "no pytest" is now too strict.

A cold `install.sh` build in a fresh directory took 5.8 s. It fetches uv 0.13.7, CPython 3.11.18 and 78 wheels, writes nothing to HOME and asks no questions. On ubuntu-latest it would run under dash: /bin/sh is bash on this cluster, so dash compatibility is untested.

Building the whole app with server_app.setup_app (constructed only, never served) works on the template conf with no SLURM call: 75 routes in 5.1 s. A start/curl/stop smoke job on ubuntu-latest is about 25 lines of shell, and the only hard input is a conf.yaml.

Everything except the cluster tier fits in about 1 minute on a free runner. I recommend one `./crboost ci` entry point that both the GitHub workflow and the maintainer run.

**CI-5 [medium, effort S] A headless serve smoke test on ubuntu-latest is feasible; the only hard input is conf.yaml**

What startup does, from the code:
- crboost.py surveys ports from /proc (services/port_survey.py:126-161, Linux only, fine on runners) and binds with claim(). An explicit --port skips the 'already running here' check (crboost.py:133) and does not write ~/.crboost/ports.json.
- setup_logging writes ~/.crboost/logs/crboost-<port>.log (services/log_setup.py:29, 235).
- read_or_create_secret writes ~/.crboost/token (services/server_auth.py:48-60).
- server_app.setup_app builds CryoBoostBackend (server_app.py:143), which loads config (backend.py:256). That is the only hard dependency: no conf.yaml means FileNotFoundError.
- Startup handlers: LoopWatchdog, workers.warm_up (one spawned worker, services/workers.py:193-197), then PipelineMonitor._discover_and_recover. It reads prefs from the empty HOME and the template's DefaultProjectBase, logs 'base path missing; skipping' (pipeline_monitor.py:138-140), and ticks only over loaded projects (none).

Why missing SLURM is harmless: SlurmService._run_command wraps create_subprocess_exec in except Exception and returns (False, '', msg) (slurm_service.py:486-500), so the landing status strip's sinfo/sacctmgr calls (ui/landing_status_strip.py:160, 202) degrade instead of crashing. supervisor_owner's squeue catches OSError (services/supervisor_owner.py:158-162).

Measured, without serving: setup_app(24399) on the template conf with a throwaway HOME built 75 routes in 5.1 s and created only ~/.crboost/{secret,nicegui}.

Caveats:
- The socket listens from claim() (crboost.py:147) before the app is up. Early requests sit in the backlog, so curl needs --max-time and a poll loop.
- With no tty the banner prints the token and URL in plain text to stdout (crboost.py:56-58, 178). In a public Actions log, mask it.
- With no --host it binds every interface, IPv6 dual-stack (port_survey.py:330-341). Use --host 127.0.0.1.
- The Google Fonts link in the page head (server_app.py:132-138) matters only to browsers.

Evidence:
- crboost.py:121-189
- server_app.py:60-182
- services/server_auth.py:21-24, 48-60
- services/scheduling_and_orchestration/pipeline_monitor.py:102-150
- services/computing/slurm_service.py:486-500
- scratch run: 'constructed FastAPI 75 routes; startup handlers: 1', WALL 5.11 s

Recommendation: A CI step:
1. export HOME=$(mktemp -d); cp the conf and qsub templates.
2. Start `CRBOOST_PLAIN_LOG=1 ./crboost --port 24300 --host 127.0.0.1 > srv.out 2>&1 &`.
3. Poll `curl -s -o /dev/null --max-time 2 -w '%{http_code}' http://127.0.0.1:24300/` until 401 (the token gate answers), at most 60 s.
4. tok=$(cat $HOME/.crboost/token); echo "::add-mask::$tok".
5. `curl -fsS -H "Authorization: Bearer $tok" .../` and grep for the page title.
6. `curl -fsS -H ... /api/v1/tools` and check the verb list.
7. Check that `/?token=$tok` gives a 307 with a Set-Cookie.
8. kill -TERM, wait; graceful shutdown is 5 s (server_app.py:39).
9. Fail if grep -q Traceback $HOME/.crboost/logs/crboost-24300.log.

About 1 minute on a runner, cold env included.

- Keep pushing straight to main? Recommended yes for 1–2 maintainers, with CI on every push and rulesets only on `v*` tags and `stable`. Requiring PRs would raise the Scorecard score and enable PR-based notes, but slows the current pace.
- Dependency bumps before the December tag: recommended yes for requests, pillow and starlette (via fastapi) now, and nicegui 3.0.3→3.12.x as a dedicated UI test pass. Also recommended: drop the requirements.in:10 rule tying numpy, pandas, scipy and requests to the cluster's 2023 modules, since the environment no longer uses them.
- Update notice: recommended a no-network default (read origin/stable and tags after the admin's `git fetch`) plus an opt-in `update_check: true` that makes one call a day per install to the `/releases/latest` redirect. Alternative: an on-by-default outbound check, Grafana-style.
- Docs site for December: recommended none (curated README and docs index on GitHub). Later: Zensical on GitHub Pages; Read the Docs if per-tag versioned docs are wanted.
- Zenodo DOI with the first release: recommended yes, after the repo cleanup, with CITATION.cff only. The PI must supply the author list and ORCIDs, and an org admin must approve the Zenodo app.
- Format debt: recommended one `ruff format .` commit (48 files) recorded in .git-blame-ignore-revs before CI turns on, rather than excluding files.
- check_look_literals.py in CI: recommended non-blocking until the current offenders are fixed, then blocking.
- Patch releases: recommended tagging patches from main while main is releasable; keep a `release/YYYY.M` branch with cherry-picks only when main is mid-refactor.
- Tag signing: recommended SSH-signed annotated tags plus immutable releases; this needs the maintainer's signing key uploaded to GitHub as a signing key.
- Dependency-update bot: recommended Dependabot (`uv` + `github-actions`, monthly, grouped, 7-day cooldown) with the CI lock-sync gate. Renovate only if the lock header is changed to drop `--config-file` and `-o`.

## recon:onboarding: A new site installs CryoBoost end to end (the Munich case): fresh clone, install, preflight, self-test, images, updates, and what ties it to the current cluster

I cloned HEAD (80a874b) into scratch and installed it exactly as the README says. The Python side works well. `./install.sh` took 6.7 s and fetched uv 0.13.7, CPython 3.11.18 and 78 wheels into a 1.5 GB `.uv/`, with no edits needed. Preflight's messages tell an admin what to fix: on the untouched template it lists 14 failures, each naming the key. The static self-test runs in 1.8 s. The code holds no CBE partition names or paths (roadmap 20 S2e held); the friction is elsewhere.

1. **Tool images (the biggest gap).** The install doc's table points at four old, partly unpinned .def files (RELION on branch `ver5.0`, IsoNet2 at HEAD, Miniconda "latest"), while production runs the `*_sm100` builds. The easymode .def exists only on the lab filesystem. The napari image is not mentioned in the install doc at all. The images in use total 82.4 GB, all built by hand.
2. **Nothing checks that an image is what the code expects.** Preflight only checks that each image path is a file. With the docs' minimal example and three 4-byte fake .sif files, preflight said "All checks passed" and the static test passed.
3. **The template ships CBE-only values that no check catches.** missAlign asks for `gpu:nvidia_b200:1` and `qos: g_medium`, and IsoNet train asks for `g_medium`. Preflight checks only partition names, and the cluster self-test only uses `slurm_defaults`. At a second site, sbatch rejects those jobs the first time they run.
4. **Updates are silent.**
   - There are no tags, no version, no changelog and no update notice; a site follows a `main` that got 393 commits since 2026-09-15.
   - `conf.yaml` is untracked, and the conf template changed 39 times in that period.
   - Test: a conf filled from the template as it stood at the 2026-10-15 handoff loads under HEAD with 0 warnings, yet 61 keys of today's template are missing from it: whole job profiles, `tools.tilt_filter`, `napari`, `ood`. Memory values the newer template raised also stay old in such a conf (tsCtf 8G vs 32G now, tmextractcand 8G vs 24G).
   - Image rebuilds an update needs (6 .def commits since 10-16, two of them new required images) show up only when a job fails.
5. **Site config, code and Python environment share one checkout.** A `git pull` changes the code that running servers and queued jobs run. The launcher and REPO_ROOT already resolve symlinks, so versioned release folders behind a `current` link, with the site config outside them, would fix this cheaply.
6. **Things a site gets by hand with no check.**
   - The tilt-filter weights: unpublished; preflight says nothing; the job fails when DL mode is picked.
   - cisTEM (4.3 GB, but only `simulate` is used).
   - The easymode weights (4.0 GB).
7. **Node requirements nobody documents or checks:** the MPS daemon (template matching runs 3 lanes by default), an NVIDIA driver new enough for the CUDA 12.9 images, ssh from headnode to compute nodes for ChimeraX, and SLURM accounting.
8. **No end-to-end check after install.** The copia protocol (EMPIAR-12580) is in the repo, but the install doc does not point to it as the last step.

The rest is small: stale command names in messages and docs, misleading lines in the install output, and repo clutter a public visitor sees (the tracked `memory/`, stale branches, `.gitignore` leftovers).

**ONB-5 [high, effort M] Site config and code share one mutable checkout: no versioned installs, and a pull changes code under running servers and queued jobs**

conf.yaml and qsub.sh are fixed at REPO_ROOT/config/. Drivers run the server's own interpreter with PYTHONPATH set to the checkout. Consequences: (1) After a `git pull`, every job (queued or newly submitted) runs the new code. (3) Two versions cannot sit side by side on one site config. The launcher and install.sh already resolve the checkout with `pwd -P`, and REPO_ROOT uses resolve(). So `releases/vX/` folders behind a `current` symlink would freeze each server and its jobs on the release it started from, once the site config lives outside the checkout.

Evidence:
- services/configs/config_service.py:31 (DEFAULT_CONFIG_PATH = REPO_ROOT/config/conf.yaml; no env override)

- crboost:14 and install.sh:19 (here=$(cd ... && pwd -P))
- docs/roadmaps/roadmap_39-python-environment-and-setup.md:480-484 (queued jobs run the code on disk at start)

Recommendation: Add `CRBOOST_SITE_DIR` (or `--site`) for conf.yaml + qsub.sh + weights, defaulting to config/ for backward compatibility.
